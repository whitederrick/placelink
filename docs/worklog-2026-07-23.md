# 2026-07-23 작업 정리

## 완료한 작업

### PostGIS shadow DB 복구

- `pnpm db:migrate`의 `P3006/P3018` 및 `geography` 타입 누락을 재현했다.
- 기존 마이그레이션은 수정하지 않고 Prisma 7의 `migrations.initShadowDb`에서 `CREATE EXTENSION IF NOT EXISTS postgis`를 실행하도록 구성했다.
- `Place.location`의 GIST 인덱스를 Prisma 스키마에 명시해 마이그레이션이 공간 인덱스를 제거하지 않도록 했다.
- Prisma Client가 장소 생성 API를 유지할 수 있도록 생성형 `location` 필드는 nullable로 정렬했다. 좌표는 필수이며 기존 DB 트리거가 insert/update 때 location을 채운다.
- `pnpm db:migrate`가 shadow DB 재생과 실제 DB 적용을 모두 완료하고 스키마 동기화 상태를 보고하는 것을 확인했다.

### 커플 라이프사이클 E2E

Windows UI 자동화 승인이 시간 초과되어, 두 개의 독립 Auth.js 쿠키 세션과 실제 SSR/API/DB를 관통하는 E2E로 검증했다.

- 기존 연결 해제 후 양쪽이 솔로 상태로 전환됨
- 과거 공동 코스가 `익명` 소유자로 렌더링됨
- 초대 생성 및 공개 랜딩 렌더링
- 자기 초대 수락 `400`
- 민지 계정의 정상 수락과 양쪽 연결 상태 반영
- 양쪽 마이페이지에서 동일한 `지훈❤️민지`, D-Day, 두 멤버 이니셜 렌더링
- 활성 커플의 새 초대 생성 `409`
- 사용된 초대 미리보기와 재수락 `404`
- 잘못된 토큰 `400`
- 어느 한쪽의 연결 해제 후 양쪽이 다시 솔로 상태로 전환됨

검증 후 `pnpm db:seed`를 다시 실행해 표준 시드 상태로 복원했다.

### 예외 흐름과 네트워크 복구

- 같은 초대에 두 개의 실제 수락 요청을 동시에 보내 `200/404`로 정확히 한 건만 성공함을 확인했다.
- 기존 `couple_members_one_active_per_user_idx` 부분 유니크 인덱스 위반이 `409`로 변환되는 회귀 테스트를 추가했다.
- 만료 시각을 과거로 조정한 실제 초대의 미리보기와 수락이 모두 `404`임을 확인했다.
- 비로그인 수락이 `401`을 반환하고, 로그인 완료 후 원래 초대 URL로 복귀함을 확인했다.
- 초대 미리보기의 네트워크·서버 실패를 만료 링크와 구분하고 `다시 시도` UI를 추가했다.
- 초대 수락 중 네트워크 오류가 발생해도 busy 상태를 해제해 다시 시도할 수 있도록 수정했다.
- 로그인 복귀 URL, 네트워크 실패, 401, 만료·사용 링크 분기를 검증하는 클라이언트 테스트 5개를 추가했다.
