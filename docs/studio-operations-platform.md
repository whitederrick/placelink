# PlaceLink Studio 운영 플랫폼 기준

## 목적

Studio는 수집 데이터 검수 화면이 아니라 PlaceLink의 서비스·콘텐츠·고객·파트너·매출을
한곳에서 관제하는 운영 플랫폼이다. 모든 운영 업무는 `요약 → 목록 → 상세 → 변경 이력`
흐름을 공유하고, 운영자가 현재 상태와 다음 조치를 한눈에 판단할 수 있어야 한다.

## 구현 상태 — 2026-09-03

- 1단계 관제 기반 중 Studio 공통 레이아웃, 홈 대시보드, `IngestionRun`, 공급자
  최근 상태, 수집 실행 목록·상세를 구현하고 운영 배포했다.
- 운영 주소는 `https://place-link.com/ko/studio`이다.
- 아직 필요한 1단계 작업은 기존 검수 화면의 완전한 목록·상세 재구성과 원본 대비,
  변경·검증 실패·병합 지표, 재시도·부분 성공·장애 알림이다.
- 2단계 사용자 목록·상세를 구현했다. 가입 경로와 상태별 필터, 닉네임·이메일·ID
  검색, 최근 활동, 커플 연결, 개인·커플 코스와 스크랩 이력을 관리자 전용 화면과
  API에서 조회할 수 있다.
- 2단계 문의·불만·신고 목록·상세와 처리 기능을 구현했다. 유형·우선순위·담당자·상태·
  처리기한을 관리하고, 고객 답변 기록과 내부 메모를 타임라인에서 확인할 수 있다.
  모든 변경은 사유를 요구하고 감사로그와 함께 저장한다.
- 다음 구현 단위는 운영자 역할·세부 권한, 사용자 상태 변경, 콘텐츠 운영이다.
- 상세 완료 내역과 정확한 후속 작업은 최신 날짜의 `docs/handoff-*` 문서를
  기준으로 한다.

## 운영 원칙

- 사용자 서비스와 운영 화면의 권한을 서버에서 분리한다.
- 공공 데이터, 파트너 입력, 에디터 입력, 사용자 제보의 출처를 항상 표시한다.
- 일반 추천과 유료 노출을 구분하고 사용자 화면에도 제휴·광고 여부를 명시한다.
- 장소·행사·코스의 원본 수집 상태와 실제 공개 상태를 분리한다.
- 쿠폰 발급, 결제, 환불, 정산, 사용자 제재는 감사로그를 남긴다.
- 금전·제재·대량 변경은 역할별 권한과 사람의 최종 승인을 요구한다.
- 목록은 검색·필터·정렬·일괄작업을, 상세는 관계 정보와 전체 변경 이력을 제공한다.

## 전체 정보 구조

### 1. 홈 대시보드

- 오늘·7일·30일 가입자, 활성 사용자, 재방문, 코스 생성·발행·스크랩 현황
- 현재 접속 추세와 주요 전환 퍼널
- 공개 장소·행사·코스 수와 검수 대기·신고 대기 수
- 공급자별 마지막 수집 성공 시각, 실패 여부, 신규·중복·오류 건수
- 미처리 문의·불만·신고, 만료 예정 행사·쿠폰, 정산 대기 금액
- 운영자가 바로 처리해야 할 항목을 우선순위 작업함으로 제공

### 2. 사용자·고객 운영

- 사용자 목록과 상세: 가입 경로, 최근 활동, 커플 연결, 코스·스크랩·쿠폰 이력
- 접속·활동 현황: DAU/WAU/MAU, 신규·재방문, 주요 화면과 전환 흐름
- 문의·불만·신고: 유형, 심각도, 담당자, 처리기한, 상태, 답변과 내부 메모
- 제재: 경고·일시정지·차단, 사유, 기간, 증빙, 이의제기와 감사로그
- 개인정보 관련 요청: 열람·수정·탈퇴·삭제 처리 상태

### 3. 콘텐츠 운영

- 장소 목록·상세: 장소 유형, 운영 주체, 주소·좌표, 운영시간, 링크, 출처, 연결 행사
- 행사 목록·상세: 유형, 기간·회차, 가격, 예약 링크, 출처, 공개·만료 상태
- 코스 목록·상세: 작성 주체, 출처, 장소 구성, 공개 상태, 신고·성과 지표
- 홈·검색·추천 노출: 편집 슬롯, 노출 기간, 대상 지역·사용자, 우선순위
- 중복·품질 관리: 장소 병합 후보, 누락 필드, 오래된 정보, 출처 간 충돌

### 4. 데이터 운영

- 공급자: 서울시, 문화포털 등 공급자별 상태, 인증 설정 여부, 호출 한도, 담당 정보
- 수집 실행: 실행 단위의 시작·종료 시각, 성공·부분 성공·실패, 소요시간과 오류
- 수집 결과: 조회 수, 신규 수, 변경 수, 중복 수, 검증 실패 수, 병합 수
- 검수 큐: 원본과 정규화 값 비교, 유사 장소·행사 비교, 승인·반려·일괄처리
- 실행 상세에서 해당 실행의 원본 레코드, 오류, 재실행 결과를 함께 조회

현재의 `IngestionRecord`와 `AuditLog` 외에 실행 단위를 나타내는 `IngestionRun`이
필요하다. 공급자 건강 상태와 실행 이력을 이 모델을 기준으로 집계한다.

### 5. 파트너·제휴 운영

- 파트너 업체와 담당자, 사업자 확인, 계약 상태, 정산 정보 상태
- 파트너가 소유·관리하는 식당·카페·문화시설과 소유권 승인 이력
- 제휴 상품, 예약·구매 링크, 수수료 조건과 적용 기간
- 파트너별 노출·조회·스크랩·쿠폰 사용·예약 전환 성과
- 향후 파트너 포털은 실제 제휴 계약과 반복적인 셀프서비스 수요가 확인될 때 분리

### 6. 캠페인·쿠폰·이벤트

- 캠페인: 목적, 대상, 예산·수량, 기간, 파트너, 연결 장소·행사, 노출 위치
- 쿠폰: 할인 방식, 발급 조건, 재고, 사용자별 제한, 유효기간, 사용처
- 발급·사용: 발급·예약·사용·취소·만료 상태와 멱등키
- 이벤트: 응모 조건, 당첨 정책, 경품, 개인정보 동의, 결과와 지급 상태
- 성과: 노출, 클릭, 발급, 사용, 전환, 비용과 파트너별 정산 기준

### 7. 예약·결제·매출·정산

- 초기에는 외부 공식 예약 링크와 성과 추적을 우선한다.
- 이후 예약 주문, 결제 시도, 승인·취소·환불, 웹훅 처리 이력을 분리 저장한다.
- 파트너별 수수료, 쿠폰 부담 주체, 정산 대상·보류·완료 금액을 관리한다.
- 결제·환불·정산은 서명 검증, 멱등 처리, 원장형 변경 이력과 대사 절차를 갖춘다.
- 직접 결제 도입 전 전자상거래, 환불, 개인정보, 세무·정산 운영 검토를 완료한다.

### 8. 시스템 운영

- 운영자 계정, 역할과 세부 권한
- 감사로그: 행위자, 대상, 변경 전후, 사유, 시각
- 배치·외부 API 상태와 장애 알림
- 기능 플래그, 운영 공지, 약관·정책 버전

## 역할과 권한

- `SUPER_ADMIN`: 운영자와 권한, 시스템 설정, 금전 관련 최종 승인
- `OPERATIONS`: 장소·행사·코스·수집 데이터 운영
- `SUPPORT`: 문의·불만·신고 처리, 제한된 사용자 정보 조회
- `PARTNERSHIP`: 파트너·계약·캠페인 관리
- `MARKETING`: 노출·이벤트·쿠폰 기획과 성과 조회
- `FINANCE`: 결제·환불·정산·대사 조회와 승인
- `ANALYST`: 개인정보를 최소화한 통계 읽기 전용

초기에는 한 운영자가 여러 역할을 가질 수 있으나, API 권한은 처음부터 역할 단위로
검사할 수 있게 설계한다.

## 공통 화면 패턴

### 목록

- 저장 가능한 필터, 검색, 정렬, 기간 선택, 열 표시 설정
- 상태별 건수 탭과 일괄 작업
- 담당자, 최신 변경 시각, 주의 상태를 행에서 확인
- 데스크톱은 표, 좁은 화면은 동일 정보를 카드로 표현

### 상세

- 상단에 상태, 핵심 식별정보, 담당자와 주요 조치
- 본문은 기본정보, 관계정보, 성과, 원본·기술정보로 구분
- 오른쪽 또는 하단에 활동 타임라인, 내부 메모, 감사로그
- 삭제보다 비활성화·보관을 우선하고 위험 작업은 사유를 요구

## 수익모델 우선순위

1. 제휴 예약·구매 링크의 성과 수수료
2. 쿠폰·캠페인 운영비와 사용 실적 기반 과금
3. 제휴임을 명시한 프로모션 노출
4. 파트너용 분석·매장관리·쿠폰 발행 구독
5. 사용성이 검증된 이후 사용자 프리미엄 구독
6. 환불·정산 체계가 준비된 이후 직접 예약·결제 중개

## 구축 순서

### 1단계: 관제 기반

- Studio 공통 레이아웃과 전체 메뉴
- 홈 대시보드
- `IngestionRun`과 공급자 상태, 수집 실행 목록·상세
- 기존 검수 화면을 목록·상세 구조로 개편

### 2단계: 핵심 운영

- 장소·행사·코스 목록·상세와 공개 상태 관리
- 사용자 현황, 문의·불만·신고와 처리 이력
- 운영자 역할·권한과 감사로그 조회

### 3단계: 제휴와 성장

- 파트너·매장 소유권·계약 상태
- 캠페인·쿠폰·이벤트와 사용자 쿠폰함
- 제휴 성과 추적과 기본 정산 자료

### 4단계: 거래

- 예약·주문·결제·환불
- 수수료 원장, 파트너 정산과 대사
- 필요 시 별도 파트너 포털 분리

각 단계는 화면만 추가하지 않고 상태 모델, 권한, 감사로그, 운영 지표를 함께 제공해야
완료된 것으로 본다.
