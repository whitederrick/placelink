## 완료한 작업

### 사용자 핵심 흐름 QA

- 로컬 E2E에서 관리자 계정을 안정적으로 사용할 수 있게 했다.
- 행사 관리의 표준 Studio 경로를 기준으로 테스트를 정리했다.
- 커플, 코스, 탐색, 홈 피드, 모바일 핵심 흐름을 포함한 전체 브라우저 테스트를
  통과했다.

### Studio 사용자 관리

- 사용자 목록에서 닉네임·이메일·ID 검색, 계정 상태 및 가입 경로 필터를 제공한다.
- 사용자 상세에서 계정, 커플 연결, 개인·커플 코스, 스크랩과 최근 활동을 조회한다.
- 화면과 API는 관리자 전용이며 현재 읽기 전용이다.

### Studio 문의·불만·신고 관리

- 문의, 불만, 신고, 개인정보 요청을 유형·우선순위·상태·담당자·처리기한으로
  관리한다.
- 운영자 답변 기록과 내부 메모를 타임라인에 저장한다.
- 상태 변경은 사유를 요구하고 데이터 변경과 감사로그를 한 트랜잭션으로 저장한다.
- 다른 운영자의 변경을 덮어쓰지 않도록 최신 변경 시각 기반 충돌 검사를 적용한다.
- `SupportCase`, `SupportCaseEntry` 스키마와
  `20260903170000_add_support_cases` 마이그레이션을 추가했다.

### Studio 감사로그 조회

- 작업명·실행 주체·대상 ID 검색을 제공한다.
- 운영자·자동화 및 대상 유형 필터를 제공한다.
- 각 기록의 변경 전후 JSON 스냅샷을 펼쳐 확인할 수 있다.
- 화면과 `GET /api/v1/admin/audit-logs` API는 관리자 전용 읽기 기능이다.

### Studio 역할·권한과 사용자 상태 변경

- `SUPER_ADMIN`, `SUPPORT`, `CONTENT`, `ANALYST` 역할과 기능 단위 권한 매트릭스를
  추가했다. 기존 환경변수 기반 관리자는 `SUPER_ADMIN`으로 호환된다.
- 고객지원, 콘텐츠, 수집, 분석, 감사로그 서비스가 각자의 읽기·변경 권한을
  검사하며 API 래퍼도 기능 권한을 직접 요구할 수 있다.
- 사용자 상세에서 정지·복구·탈퇴를 사유와 정지 기간과 함께 처리한다.
- 사용자 상태 변경과 감사로그는 한 트랜잭션으로 저장하며 최신 수정 시각 기반
  충돌 검사를 적용한다.
- 자기 계정 상태 변경과 운영자 계정 제재를 차단했다. 탈퇴는 `SUPER_ADMIN`만
  실행할 수 있고 Studio에서 복구할 수 없다.
- `studio_role`, 상태 변경 사유·정지 종료 시각·변경 시각을 위한 마이그레이션을
  추가했다.
- `SUPER_ADMIN` 전용 운영자 권한 화면과 API를 추가했다. 사용자 검색 후 역할을
  지정·변경·해제할 수 있으며 자기 역할 변경과 마지막 최고 관리자 제거를 막는다.
- 운영자 역할 변경도 최신 수정 시각 기반 충돌 검사와 감사로그 원자 저장을
  적용한다.

## 알려진 제한

- 권한은 아직 세부 역할이 아니라 기존 `ADMIN` 단일 역할을 사용한다.
- 사용자 상태 변경, 제재, 개인정보 요청 실행 기능은 없다.
- 사용자용 문의 접수 경로와 요청 빈도 제한은 없다.
- `STAFF_REPLY`는 운영 기록이며 실제 이메일·푸시·앱 알림을 발송하지 않는다.
- 신고 대상 콘텐츠의 비공개·복구 등 후속 조치가 연결되지 않았다.
- 운영 데이터베이스 마이그레이션과 배포는 수행하지 않았다.
