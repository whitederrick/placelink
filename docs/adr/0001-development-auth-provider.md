# ADR 0001 — 개발 환경 시드 인증 공급자

## 배경

운영 인증은 Auth.js의 Kakao/Google OAuth로 확정되어 있다. 로컬 UI와 인증 필수 API를 검증하려면 외부 OAuth 키와 콜백 도메인 없이도 재현 가능한 세션이 필요하다.

## 결정

- `NODE_ENV !== production`일 때만 Auth.js Credentials 공급자를 등록한다.
- 표준 시드의 `seed-user-jihoon`, `seed-user-minji`를 각각 별도 공급자로 노출하고, 선택한 사용자가 활성 상태인지 DB에서 확인한 뒤 세션을 발급한다.
- 허용하는 개발 사용자 ID는 Zod enum으로 제한해 임의 사용자 ID를 인증 입력으로 받지 않는다.
- 운영 빌드에는 해당 공급자를 등록하지 않는다.
- 모든 인증 필수 API는 세션 토큰만 신뢰하지 않고 요청 시 User 활성 상태를 다시 조회해 Actor를 만든다.

## 대안

- 모든 개발자가 Kakao/Google OAuth 앱을 구성: 재현 비용과 콜백 설정 부담이 크다.
- 헤더나 고정 쿠키로 사용자 우회: 운영 유입 위험이 있어 배제한다.
- 인증 없이 Draft API 허용: 소유권 규칙과 실제 API 계약을 검증할 수 없어 배제한다.

## 결과

시드만으로 로그인·소유권·Draft 생성뿐 아니라 두 개의 독립 세션이 필요한 커플 초대 흐름도 반복 검증할 수 있다. 운영 환경에서는 OAuth 키와 `AUTH_SECRET` 설정이 필수다.
