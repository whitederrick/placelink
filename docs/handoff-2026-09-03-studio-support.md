- Studio에서 기존 감사로그를 검색·필터링하고 변경 전후를 확인할 수 있다.
- 로컬 개발 데이터베이스에 신규 마이그레이션을 적용했다.
- 원격 저장소 반영, 운영 데이터베이스 마이그레이션, 배포는 수행하지 않았다.

## 구현 내용

- `/{locale}/studio/support`
  - 문의, 불만, 신고, 개인정보 요청 유형 필터
  - 낮음, 보통, 높음, 긴급 우선순위 필터
  - 접수, 처리 중, 사용자 응답 대기, 해결, 종료 상태 필터
  - 제목·본문·접수자 정보 검색과 담당자 필터
  - 처리기한 경과 표시와 커서 기반 페이지네이션
- `/{locale}/studio/support/{id}`
  - 접수자, 대상 정보, 담당자, 상태, 우선순위, 처리기한 확인
  - 상태·우선순위·담당자·처리기한 변경
  - 운영자 답변 기록과 내부 메모 타임라인
- 관리자 전용 API
  - `GET /api/v1/admin/support-cases`
  - `GET`, `PATCH /api/v1/admin/support-cases/{id}`
  - `POST /api/v1/admin/support-cases/{id}/entries`
- `SupportCase`, `SupportCaseEntry` 데이터 모델과 관련 열거형을 추가했다.
- 목록과 상세 검증용 문의·신고 시드 데이터를 추가했다.

## 안정성과 감사

- 모든 상태 변경은 운영 사유를 필수로 입력하며 데이터 변경과 감사로그 저장을 한
  트랜잭션으로 처리한다.
- 답변 기록과 내부 메모 추가도 감사로그와 같은 트랜잭션으로 처리한다.
- 상세 화면에서 읽은 최신 변경 시각을 수정 요청에 포함해 다른 운영자의 변경을
  실수로 덮어쓰지 않도록 한다. 충돌 시 API는 `409`를 반환한다.
- 화면과 API는 기존 `ADMIN` 서버 권한 검사를 사용한다.

## 현재 제한

- `STAFF_REPLY`는 운영자가 보낸 답변의 기록이다. 실제 이메일·푸시·앱 알림 발송은
  아직 연결하지 않았다.
- 사용자용 접수 API와 스팸·요청 빈도 제한은 아직 구현하지 않았다.
- 역할별 세부 권한은 후속 작업이다.

## 남은 작업과 우선순위

### P0 — 운영 안전성

1. `ADMIN` 단일 권한을 `SUPER_ADMIN`, `OPERATIONS`, `SUPPORT` 등 역할별 권한으로
   분리한다.
2. 사용자 정지·복구·탈퇴 처리에 사유, 처리 기간, 낙관적 동시성 제어와 감사로그를
   적용한다.
3. 운영 배포 전에 신규 마이그레이션을 백업·복구 절차와 함께 검증한다.

### P1 — 문의의 실제 접수와 답변

1. 사용자용 문의 접수 API와 화면을 구현한다.
2. 요청 빈도 제한, 본문 크기 제한, 개인정보 최소 수집과 악성 입력 대응을 적용한다.
3. 답변 전달용 이메일·푸시 어댑터와 발송 상태, 실패 재처리, 중복 발송 방지를
   구현한다.

### P1 — 신고 후속 조치

1. 장소·행사·코스 목록·상세에 공개 상태 관리와 신고 이력을 연결한다.
2. 신고 상세에서 대상 콘텐츠로 이동하고 비공개·복구·병합 등의 조치를 수행하게
   한다.
3. 위험 조치에는 역할 검사, 사유 입력, 변경 전후 감사로그를 적용한다.

### P2 — 운영 편의와 관제

1. 감사로그 기간 필터, 작업 유형 필터, 대상 상세 바로가기를 추가한다.
2. 처리기한 임박·초과, 긴급 신고와 답변 발송 실패 알림을 추가한다.
3. 목록 정렬, 저장 필터, 담당자별 작업함과 일괄 배정을 추가한다.

## 배포 전 확인 사항

- 운영 환경 변수와 관리자 계정·역할 구성을 확인한다.
- `20260903170000_add_support_cases` 마이그레이션을 운영 데이터베이스에 적용한다.
- 시드 데이터는 운영 환경에서 실행하지 않는다.
- 문의 상태 변경, 내부 메모, 감사로그 권한을 운영 계정으로 점검한다.
- 이메일·푸시 연결 전까지 `STAFF_REPLY`가 실제 발송으로 오해되지 않도록 운영자에게
  안내한다.
- 전체 Playwright 테스트를 신규 감사로그 테스트까지 포함해 다시 실행한다.
