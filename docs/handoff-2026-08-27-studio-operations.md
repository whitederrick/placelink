## 완료한 작업

### 1. 장소·행사·코스 출처 및 유형 구분

- 장소, 행사, 코스에 사용자 생성 콘텐츠와 외부 공급자 콘텐츠를 구분할 수 있는
  출처 체계를 마련했다.
- 카페·식당·문화시설·영화관·행사 등 콘텐츠 유형과 공공·민간 운영 주체를
  필터링 가능한 데이터로 다룰 수 있게 했다.
- 사용자 생성 코스는 신규 생성 시 `sourceType=UGC`로 기록한다.
- 장소의 일반 운영시간과 예외 휴무, 행사의 기간·회차, 공식 출처·예매 링크를
  저장할 기반을 추가했다.

### 2. 일정 데이터 수집 기반

- 서울 열린데이터광장 문화행사 수집 어댑터를 구현했다.
- 한국문화정보원 한눈에보는문화정보 조회서비스 수집 어댑터를 구현했다.
- 문화포털의 현재 운영 계약을 반영했다.
  - Base URL: `https://apis.data.go.kr/B553457/cultureinfo`
  - 기간별 목록: `/period2`
- 문화포털 XML 응답 검증, 페이지네이션, 공급자 오류 노출을 보강했다.
- 공급자 하나가 실패해도 실패 사실을 숨기지 않고 결과에 포함하도록 했다.
- Vercel 운영 환경에 일반 인증키가 등록됐고 운영 수집 호출이 성공했다.
- 매일 실행되는 통합 수집 경로는 `/api/v1/cron/ingestions/schedules`이다.

### 3. 수집 실행 이력

- `IngestionRunStatus`: `RUNNING`, `SUCCEEDED`, `FAILED`
- `IngestionTrigger`: `MANUAL`, `SCHEDULED`
- `IngestionRun` 모델을 추가했다.
  - 공급자, 실행 상태, 실행 방식, 행위자
  - 요청 조건
  - 공급자 전체 건수, 조회·선별·신규·중복 건수
  - 시작·종료 시각, 오류 메시지
- `IngestionRecord`가 자신을 만든 `IngestionRun`을 선택적으로 참조한다.
- 성공과 실패 모두 실행 이력과 감사로그에 남는다.
- 상태·공급자·시각 기준 조회 인덱스를 추가했다.

### 4. Studio 1단계 운영 화면

- 공통 Studio 레이아웃과 사이드바를 구현했다.
- 대시보드에 다음 요약을 제공한다.
  - 사용자 수와 7일 신규 사용자
  - 최근 15분 활동 이벤트
  - 공개 코스와 진행 중 행사
  - 검수 대기 데이터와 최근 24시간 수집 실패
  - 서울시·문화포털 최근 수집 상태
  - 최근 수집 실행 목록
- 수집 실행 목록을 검색·상태·공급자·실행 방식으로 필터링할 수 있다.
- 실행 상세에서 요청 조건, 실행 주체, 시작·종료 시각, 처리 건수, 오류와 생성
  레코드를 조회할 수 있다.
- 실행 상세의 레코드에서 기존 검수 목록으로 이동할 수 있다.
- 관리자 전용 읽기 API를 추가했다.
  - `GET /api/v1/admin/ingestion-runs`
  - `GET /api/v1/admin/ingestion-runs/:id`
- 비로그인 및 비관리자 접근은 서버에서 차단한다.
- 아직 구현하지 않은 사용자·제휴·캠페인·매출 메뉴는 계획 상태로 표시한다.

### 5. 운영 플랫폼 전체 설계

- `docs/studio-operations-platform.md`에 다음 영역의 거시적 구조를 정의했다.
  - 홈 대시보드
  - 사용자·고객 운영
  - 콘텐츠 운영
  - 데이터 운영
  - 파트너·제휴
  - 캠페인·쿠폰·이벤트

- 수익모델 우선순위는 외부 예약 링크 성과 수수료, 쿠폰·캠페인, 명시된

### 6. 운영 배포와 DB 배포 절차

- Production Vercel 빌드에서만 Prisma migration을 먼저 적용하도록
  `apps/web/scripts/build.mjs`를 추가했다.
- 앱의 일반 쿼리는 Supabase Transaction Pooler `6543`을 계속 사용한다.
- Production migration 실행 시에만 같은 연결의 포트를 Session Pooler `5432`로
  바꿔 advisory lock과 DDL 실행이 가능하도록 했다.
- 비밀번호나 전체 `DATABASE_URL`을 파일·로그·Git에 기록하지 않았다.
- 6543에서 대기하던 실패 배포 `dpl_FVX4s41Q8X9BCTwvnx557KSWBdtP`는 제거했다.
- 최종 Production 빌드에서 10개 migration을 확인했고 신규 migration 적용과
  Next.js 빌드를 모두 성공했다.

## 현재 제약과 정확한 의미

- 대시보드의 `최근 15분 활동`은 현재 접속자 수가 아니라 15분 동안 수집된
  분석 이벤트 수다. 실시간 동시접속자는 별도 세션/heartbeat 설계가 필요하다.
- 공급자 상태는 현재 실제 연결된 서울시와 문화포털 중심이다.
- 수집 실행 상태는 현재 성공·실패 중심이며 부분 성공, 재시도 횟수, 검증 실패,
  변경·병합 건수는 아직 별도 지표가 아니다.
- Studio에는 아직 사용자 상세, 문의 처리, 제휴, 쿠폰, 결제 기능이 없다.
- 운영 DB와 Preview DB가 같은지 다시 확인하고 장기적으로 분리해야 한다.
- 현재 브랜치는 `main`이 아니다. PR·필수 CI·병합 여부를 다음 단계에서 확인한다.
